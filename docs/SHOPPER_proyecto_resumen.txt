  4. LO QUE HEMOS CONSTRUIDO — DETALLE
================================================================

----------------------------------------------------------------
  BACKEND
----------------------------------------------------------------

  BASES DE DATOS (sin ORM)
  ─────────────────────────
  • PostgresModule (@Global) → inyecta POSTGRES_POOL en toda la app
  • MongodbModule  (@Global) → inyecta MONGO_CLIENT en toda la app
  • Ambos disponibles sin importar los módulos en cada feature

  MÓDULO AUTH
  ────────────
  • Registro con hash bcrypt (salt rounds: 10)
  • Login con email + contraseña (passport-local)
  • Access Token  → JWT expira en 15 minutos
  • Refresh Token → JWT expira en 7 días, hasheado en BD
  • Refresh automático cuando el access token expira
  • Logout invalida el refresh token en PostgreSQL
  • JwtStrategy   → extrae usuario del Bearer token
  • RolesGuard    → bloquea acceso según rol requerido
  • @Roles()      → decorador para marcar rutas por rol
  • @CurrentUser() → decorador para obtener usuario del request

  MÓDULO USERS (PostgreSQL)
  ──────────────────────────
  • Tabla: users (id UUID, name, email, password_hash, role, refresh_token_hash)
  • findByEmail, findById, create, updateRefreshToken
  • Queries directas con pg Pool

  MÓDULO STORES (PostgreSQL)
  ───────────────────────────
  • Tabla: stores (id UUID, owner_id, name, slug, description, logo_url, theme, is_published)
  • CRUD completo con verificación de ownership
  • Solo owner de la tienda o admin puede editar/eliminar
  • Update dinámico (solo actualiza los campos enviados)
  • Slug único por tienda

  MÓDULO PRODUCTS (MongoDB)
  ──────────────────────────
  • Colección: products
  • Campos: store_id, title, sku, price, stock, images[], variants[], attributes{}, is_active
  • Variantes con SKU, precio, stock y atributos dinámicos propios
  • Soft delete (is_active: false en vez de eliminar físicamente)
  • Verificación que el producto pertenece a la tienda del owner

  SISTEMA DE ROLES
  ─────────────────
  • super_admin → acceso total a toda la plataforma
  • admin       → gestiona tiendas y owners
  • owner       → gestiona su propia tienda y productos
  • buyer       → comprador, acceso al portal público

  ENDPOINTS DISPONIBLES
  ──────────────────────
  POST   /auth/register              → crear cuenta
  POST   /auth/login                 → iniciar sesión
  POST   /auth/refresh               → renovar tokens
  POST   /auth/logout                → cerrar sesión

  GET    /stores                     → listar tiendas
  POST   /stores                     → crear tienda (admin)
  GET    /stores/my                  → mis tiendas (owner)
  GET    /stores/:id                 → ver tienda
  PATCH  /stores/:id                 → editar tienda
  DELETE /stores/:id                 → eliminar tienda

  GET    /stores/:storeId/products   → listar productos
  POST   /stores/:storeId/products   → crear producto (owner)
  GET    /stores/:storeId/products/:id   → ver producto
  PATCH  /stores/:storeId/products/:id   → editar producto
  DELETE /stores/:storeId/products/:id   → eliminar producto

     cd C:\SHOPPER\frontend
     npm run dev

  • Frontend  → http://localhost:3000
