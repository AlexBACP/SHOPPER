================================================================
  10. QUÉ MEJORAR — ROADMAP SUGERIDO
================================================================

  ── PRIORIDAD ALTA (impacto en usuario final) ──────────────────

  [ ] PAGOS REALES
      El checkout actual solo simula el pago (UI completa, sin integración).
      Integrar: Wompi (Colombia) o MercadoPago.
      Wompi tiene sandbox gratis y es el estándar colombiano.
      Requiere: widget Wompi en el frontend + webhook en el backend.

  [ ] NOTIFICACIONES EN TIEMPO REAL
      Cuando llega un pedido al vendedor no recibe aviso inmediato.
      Implementar con: Socket.io (ya tiene NestJS) o Server-Sent Events.
      Mostrar badge en el sidebar + toast cuando llegue un pedido nuevo.

  [ ] IMÁGENES EN PRODUCTOS
      El ImageUploader sube a Cloudinary pero la URL se guarda en MongoDB
      sin optimización. Mejorar:
      - Transformaciones automáticas de Cloudinary (resize, webp)
      - Lazy loading con next/image
      - Placeholder blur mientras carga

  [ ] BÚSQUEDA DE PRODUCTOS
      Actualmente solo hay búsqueda de tiendas en la home.
      Agregar /search?q=... con búsqueda full-text en MongoDB.
      La página /search/page.tsx ya existe en el directorio.

  ── PRIORIDAD MEDIA (mejora de experiencia) ────────────────────

  [ ] SEGUIMIENTO DE PEDIDOS
      El buyer puede ver el estado pero no hay timeline visual.
      Crear un componente TimelineEstado con los pasos: pending →
      confirmed → processing → shipped → delivered con fechas.

  [ ] EMAILS TRANSACCIONALES
      Resend ya está integrado pero solo envía bienvenida.
      Agregar: confirmación de pedido, cambio de estado, factura PDF.

  [ ] RESEÑAS Y CALIFICACIONES
      Los productos no tienen sistema de reviews.
      Tabla nueva en PostgreSQL: reviews(id, product_id, user_id, rating, comment).
      Mostrar estrellas en la tienda pública.

  [ ] PÁGINA DE PRODUCTO INDIVIDUAL
      /store/[slug]/product/[id]/page.tsx existe pero está básica.
      Mejorar: galería de imágenes, zoom, selector de variantes,
      productos relacionados, descripción con markdown.

  [ ] PERFIL PÚBLICO DEL VENDEDOR
      Agregar bio, foto de perfil, redes sociales a las tiendas.
      Mostrar en la página pública /store/[slug].

  [ ] APPLE SIGN IN
      Requiere: cuenta Apple Developer ($99/año), Service ID,
      clave privada .p8, Team ID, Key ID.
      La infraestructura backend ya está lista (solo falta la strategy).
      Usar: @nicokaiser/passport-apple

  ── PRIORIDAD BAJA (técnica / deuda) ───────────────────────────

  [ ] PERSISTENCIA DEL CARRITO EN BASE DE DATOS
      El carrito actual vive solo en localStorage (Zustand persist).
      Si el usuario cambia de dispositivo pierde el carrito.
      Guardar en tabla cart_items en PostgreSQL.

  [ ] PWA / MANIFEST
      Agregar: manifest.json con colores dorados, iconos 192/512,
      service worker básico para cache offline.
      Color: #f59e0b (dorado de la marca).

  [ ] SEO Y META TAGS
      Las páginas públicas (tiendas, productos) no tienen OG tags.
      Usar generateMetadata en Next.js 14 para título, descripción,
      imagen OG dinámica por tienda/producto.

  [ ] ANALYTICS REALES
      Los stats de la home (1200 productos, 850 compradores) son
      hardcoded. Crear endpoint GET /stats que los calcule en tiempo real.

  [ ] PAGINACIÓN
      La lista de tiendas en admin y la vitrina pública cargan todo.
      Implementar cursor-based pagination en los endpoints del backend.

  [ ] TESTS
      No hay tests automatizados.
      Empezar con: Jest para el backend (auth.service, users.service)
      y Playwright para los flujos críticos (login, checkout).

  [ ] OPTIMIZACIÓN DE RENDIMIENTO
      - Instrument Serif: preload en <head> o variable font
      - Imágenes: migrar <img> → next/image con lazy loading
      - Bundle: revisar con next build --debug qué pesa más
      - Framer Motion: lazy import en páginas con muchas animaciones

  [ ] MODO CLARO
      ThemeProvider existe pero el tema claro no está diseñado.
      El sistema de variables CSS en globals.css está preparado para
      agregar un bloque .light { } con los valores claros.
